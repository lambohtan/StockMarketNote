# V2 确定性排名与 Top10
状态：DRAFT
实现状态：未实现
截至：2026-08-30

本文规定未来预筛、跨股票排名和 Top10 输出的确定性边界；排名配置、权重和代码路径尚未存在，以下接口不是当前代码。

## 两级确定性处理

1. Python 对多来源候选并集执行约 20–30 个 ticker 的确定性预筛。
2. 每个入选 ticker 经过隔离的 Agent 研究和 Research Verdict 验证。
3. Python 再对合格的 validated Research Verdict 执行跨股票确定性排名。
4. 报告层消费有稳定顺序的结果，不能反过来让 LLM 决定入选或排名。

## 排名规则

- LLM 自由文本永远不直接进入 rank key。`research_summary`、bull/bear prose 和风险文字只能通过后续明确批准的结构化字段影响资格或展示。
- 排名配置必须版本化，并在实现前单独批准；本次仓库重组不批准任何权重、阈值、缺失值替代或评分卡。
- unknown 与 zero、negative 各自独立。缺失事实不能自动变成 0，也不能自动成为负分；资格判断要保留 unknown 的原因。
- 每个被排名项目必须保留 `data_quality` 和 evidence-completeness 字段，以及使用的配置版本和分析日期。
- tie-break 必须稳定、可复现、与运行顺序无关，最终以 normalized ticker ordering 作为确定性末级键。
- 排名键必须来自可追溯的 Python/provider 数值事实或经批准的结构化 verdict 字段，不来自未经验证的自由文本。

## Top10 语义

只有在至少 10 个合格且已研究的股票对象存在时，输出才标记为 `Top 10/10` 并包含恰好十项。合格数量不足十个时，输出标记为 `Top N/10`，其中 N 是实际合格数量；不得用 failed、unresearched、缺证据或仅预筛未研究的对象填充。

如果没有合格对象，报告仍须明确显示 `Top 0/10` 和失败/缺口原因，不得输出看似完整的空排名。对象被排除的理由、数据质量和 evidence completeness 必须可审计。

## 安全和验证边界

排名和报告不得产生买入、卖出、仓位、目标价或预测承诺。研究不足、来源失败、Verdict 验证失败和配置未批准都要阻止把结果表述为最终排名。静态规则测试不能证明真实 provider 数据、速率限制或手机投递通过；这些属于独立的后续验收。

本文件只为未来实现提供规则，不创建 Python ranker、权重配置、数据库 schema 或报告代码。
