# P4 设计：股票池 + LLM 深读 + 交叉验证倾向标签

日期：2026-08-28
状态：已与用户确认，待写实施计划
取代：HANDOFF §7 里的「P4 评分卡（100 分）」草案 —— **那版作废**

---

## 0. 为什么推翻原来的 P4

原 P4 设计是一张 100 分评分卡（关注度 25 / 趋势 30 / 基本面 30 / 组合契合 15），
全部由 Python 打分。用户在 2026-08-28 提出：这不是他要的东西。

他要的是：**导入股票池 → LLM 读每只票的财报和新闻 → 告诉他当天讨论度高的票发生了什么、
在他的标准下算不算符合。**

复核代码后确认用户的判断成立：

- 整条日报链路里 LLM 只有一处调用（`run_daily.py:111`）
- 喂给它的材料是 8-K 的一行标题描述、新闻的**标题**（`sw/sources/news.py` 只取 title/url）、
  财报的**日期**（不是内容）
- `edgar_filings` 表只存申报元数据，**从未下载过任何正文**
- 且只对残差 >2σ 的异动票调用

也就是说「LLM 帮我看财报和新闻」这件事，此前一行代码都没有。
原 P4 继续做评分卡，只会让「全是 py 在算数」的问题更严重。

**本设计把 P4 重新定义为：材料层（下正文）+ 双路判定（py 与 LLM 交叉验证）+ 倾向标签。**

---

## 1. 目标与非目标

### 目标

1. 每天自动构建股票池：持仓异动 + ApeWisdom 前 20 + Form 4 申报集中
2. 对入选的票下载**财报正文与新闻正文**，交给 LLM 深读
3. 输出固定四段：发生了什么 / 多头论点 / 空头论点 / 接下来盯什么
4. 输出一个**带理由的倾向标签**（偏正面 / 中性 / 偏负面 + 命中了哪几条标准）
5. py 与 LLM 对同一批材料**各自独立判定**，分歧逐条暴露
6. 一只票一条 ntfy 推送，全文进 markdown 报告

### 非目标

- 不做 13F（滞后 45 天，进不了日更；用户 2026-08-28 明确决定本期拿掉）
- 不做目标价、不做仓位建议、不做买卖指令（见 §9 产品原则）
- 不做 Web UI（仍是 P6）
- 不做回测（P7）
- 不预测涨跌

## 3. 架构

```
run_pool.py（独立 launchd 任务，日更，跑在 run_daily.py 之后）
  │
  ├─ 1. pool.build(store, cfg, d) → 今日名单
  │       持仓异动：就地调用 analysis/attribution.attribute() 重算
  │                 （归因结果当前不落库，且重算是纯本地计算，读 prices 表即可）
  │       ApeWisdom：当日前 20 全收（含前 10）
  │       Form 4：全市场窗口内申报集中的票
  │       去重 → 持仓异动全进 + 新票按信号强度取 3
  │
  ├─ 2. 材料层（每只票）
  │       filings_text.fetch(ticker)  最新 10-Q/10-K → 抽 MD&A + 风险因素
  │                                   ↳ filing_texts 缓存命中(accession) 直接返回
  │       news_full.fetch(ticker)     3–5 条新闻正文
  │       facts.collect(store, tk)    原始数字（季度营收/现金流/毛利率/相关性/
  │                                   Form4 申报数/热度排名/PE/forward PE）
  │
  ├─ 3. 双路判定
  │       py :  criteria.evaluate(facts)              → 6 条硬指标命中表
  │       llm:  deepread.stage1(材料 + 原始数字)       → LLM 自己的 6 条判定
  │                                                     + 2 条文本判定
  │             ⚠️ stage1 输入里**不含 py 的结论**，否则它会顺着抄，
  │                交叉验证失效
  │             每条判定必须附财报原文引用
  │
  ├─ 4. deepread.stage2(py_result, llm_result, facts) → 最终输出
  │       命中 X/8 + 倾向标签
  │       四段：发生了什么 / 多头 / 空头 / 盯什么
  │       分歧节：py 与 LLM 不一致的条目逐条列出，两边理由都给
  │
  └─ 5. 出口
        reports/pool_<日期>.md      全文
        outbox(kind='pool')         一只票一条，正文截到 ntfy 上限
```

## 4. 数据库变更

```sql
-- 财报正文缓存：按 accession 唯一，读过不重读
CREATE TABLE IF NOT EXISTS filing_texts (
  accession   TEXT PRIMARY KEY,
  ticker      TEXT NOT NULL,
  form        TEXT NOT NULL,        -- 10-Q / 10-K
  filed_at    TEXT NOT NULL,
  section     TEXT NOT NULL,        -- mdna / risk_factors
  content     TEXT NOT NULL,
  fetched_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_filing_texts_ticker ON filing_texts(ticker, filed_at);

-- 深读结果快照：只追加，用于日后回看「当时是怎么判的」
CREATE TABLE IF NOT EXISTS deepread_results (
  id            INTEGER PRIMARY KEY,
  d             TEXT NOT NULL,       -- 逻辑日期
  ticker        TEXT NOT NULL,
  source        TEXT NOT NULL,       -- 入池原因：holding_anomaly / apewisdom / form4
  py_hits       TEXT NOT NULL,       -- JSON：6 条 py 判定
  llm_hits      TEXT NOT NULL,       -- JSON：8 条 LLM 判定 + 引用
  disagreements INTEGER NOT NULL,
  score_hit     INTEGER NOT NULL,
  score_total   INTEGER NOT NULL,    -- 分母，数据缺失时会小于 8
  label         TEXT NOT NULL,       -- positive / neutral / negative
  narrative     TEXT NOT NULL,       -- 四段全文
  model         TEXT NOT NULL,       -- 模型名，换模型时能区分是模型变了还是公司变了
  created_at    TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_deepread_d_ticker ON deepread_results(d, ticker);
```

`outbox.KINDS` 增加 `"pool"`。

**「写入即快照，只追加不覆盖」的落实**：`deepread_results` 每天一行一只票，
带模型名。一年后可以回看「当时判偏正面的票后来怎么样了」——
这是 P7 信号有效性追踪的数据基础，从第一天就要写。

## 5. 八条标准的口径

### py 管的 6 条（确定性，每条可追溯到具体计算）

| # | 条件 | 数据源 | 口径 |
|---|---|---|---|
| 1 | 营收同比增速 ≥ 20% | yfinance 季度利润表 | 最近一季 vs 去年同季；5 个季度刚好够 |
| 2 | 经营现金流为正 | yfinance 现金流表 | 最近一季 operating cash flow > 0 ⚠️ 见 §8 |
| 3 | 毛利率环比未恶化 | 季度利润表 | 本季毛利率 ≥ 上季 − 1pt |
| 4 | 与现有持仓相关性 < 0.5 | 复用 `analysis/risk.py` | 60 日日收益率，取与全部持仓的加权平均相关性 |
| 5 | 近 30 天 Form 4 申报 ≥ 3 份 | `edgar_filings` | **只说申报份数**。不说买入、不说几个人 —— 当前 schema 里没有申报人身份和交易方向（P3 已确认的语义边界） |
| 6 | 热度排名较 24h 前上升 ≥ 10 名 | ApeWisdom `rank_24h_ago` | 前 20 全收之后，这条负责区分「一直热」和「突然热」 |

**明确砍掉估值分位**：免费数据拿不到可靠的历史 PE 序列（yfinance 只给 5 个季度利润表
和当前 PE），硬算出来的分位是假精确 —— 正是 HANDOFF §11 警告过的那类
「看起来很聪明但错误的数字」。改为在报告里如实列出当前 PE / forward PE
两个原始数字，**不做判定、不进计分**。

### LLM 管的 2 条（必须附财报原文引用）

7. **管理层指引方向**：转强 / 持平 / 转弱 —— 读 MD&A
8. **风险因素是否新增重大项** —— 与 `filing_texts` 缓存里的上一期文本对比

## 6. 分歧计分与标签

- 计分 = py 的 6 条 + LLM 的 2 条 = **X/8**
- LLM 在 stage1 对 py 那 6 条**也独立判一遍**，仅用于对照，**不参与计分**
- 阈值：命中 ≥6 → 偏正面；3–5 → 中性；≤2 → 偏负面
- **分歧 ≥2 条时**，标签后强制附「分歧较多，此标签可信度低」，并逐条列出两边理由
- 数据缺失的条目记 `unknown`：**不算命中也不算未命中，分母缩小**
  （写成「4/6，2 条数据缺失」），绝不把「取不到数」伪装成「不符合」
- 标签旁固定标注：**「标准未经回测验证，是纪律工具不是涨跌预测」**

## 7. 输出

### 报告 `reports/pool_<日期>.md`

每只票一节：

```
### NVDA · 入池原因：热度排名 12（较 24h 前 +38）
在你的标准下：偏正面（命中 6/8）
py 命中 5/6：营收增速 94% · 现金流为正 · 毛利率环比 -0.4pt(未恶化) · Form4 申报 4 份 · 热度跃升 +38
py 未命中：与持仓相关性 0.71（偏高）
LLM 命中 1/2：风险因素无新增重大项
LLM 未命中：管理层指引转弱
⚠️ py 与 LLM 分歧 1 条：毛利率
   py：环比 -0.4pt，在 -1pt 阈值内，判未恶化
   LLM：MD&A 原文「we expect gross margin to normalize in the mid-70s」，判指引转弱
当前 PE 52.3 / forward PE 31.8（原始数字，不参与判定）

发生了什么：…
多头论点：…
空头论点：…
接下来盯什么：① … ② … ③ …

标准未经回测验证，不是涨跌预测。
```

### 推送

- 一只票一条 `outbox(kind='pool')`
- 标题：`NVDA · 偏正面 5/8 · 热度 +38`
- 正文：命中摘要 + 「发生了什么」段 + 分歧提示，截到 ntfy 上限（4KB）后附「全文见 pool_<日期>.md」
- 复用现有 `notify.drain`，跟日报一起在 `push_time` 统一发出

## 8. 错误处理

| 情况 | 行为 |
|---|---|
| 单条数据缺失 | 该条记 `unknown`，分母缩小，报告写明「X/6，2 条数据缺失」 |
| 财报正文抽取失败 | 该票跳过 LLM 的第 7、8 条，只出 py 部分，报告注明「未取到财报正文」 |
| LLM 调用失败 | 只出 py 部分 + 明写「LLM 深读失败」，**不静默补空话** |
| 某只票整体失败 | 跳过该票，其余票照常，失败计入 `source_health` |
| 深读整体失败 | 日报推送完全不受影响（独立链路） |
| 所有源失败 | 记 `source_health`，以 `kind='pool'` 推一条「今日股票池深读未产出」；沉默不等于没事 |

## 9. 产品原则合规性

对照 CLAUDE.md 的硬性约束逐条检查：

1. **不要求用户做任何事**：输出是「在你的标准下命中 X/8」+ 多空双方论点 + 盯什么。
   倾向标签是**对一组可复核标准的符合度**，不是买卖指令 ——
   正好是 HANDOFF §2.5 给「潜力」下的原始定义。
   ✅ **实测：`policy.assert_no_directives` 不需要改**（2026-08-29 在本机验证）：
   「在你的标准下：偏正面（命中 6/8）」「管理层指引转弱」「接下来盯什么」全部放行，
   「建议买入」「该减仓」仍被拦截。本期只补一组回归测试锁定这个行为，不改守卫代码。
   ⚠️ 但推送正文必须走 `MONEY_RE.sub()` 替换（新闻正文里会出现 $ 金额），
   且替换要在截断之前 —— 沿用 `daily_report.py` 已定的策略。
2. **数值计算确定性**：6 条硬指标全部 py 算，LLM 不产任何数字。
   LLM 的 2 条是**文本判断**不是数值计算，且必须附原文引用，判定结果连同模型名入库
   —— 换模型时能区分是模型变了还是公司变了。
3. **写入即快照**：`filing_texts` 与 `deepread_results` 只追加。
4. **launchd**：新增一个 plist，走既有 `sw/schedule.py`。
5. **标注未经回测**：标签旁固定标注。

## 10. 测试策略

- `criteria`：合成 facts 锁定每条边界（延续 HANDOFF §11 的教训 ——
  一眼看不出对错的统计量必须有已知答案的合成锚）
- `filings_text`：真实 10-Q 存进 `tests/fixtures/`，锁定 MD&A / 风险因素抽取
- 缓存：同一 accession 第二次调用不发网络请求；出现新 accession 才重读
- `deepread` stage2：分歧计数与标签阈值的边界（5 vs 6 分界、分歧 1 条 vs 2 条）
- 数据缺失路径：分母缩小而不是判未命中
- 守卫：倾向标签词放行、买卖指令仍被拦（正负样本双向断言）
- LLM 调用全部 mock，不在测试里花钱

## 11. 实现前必须先探测的不确定点

**建议实施计划的第一个任务就是一个探测脚本，而不是直接写实现。**

1. **EDGAR 正文章节抽取率**：各家公司的 10-Q 章节标题格式不统一
   （"Item 2. Management's Discussion" 的大小写、缩写、跨页符各不相同）。
   拿持仓里 3 只票试抽取，确认命中率。抽不到就要改用 edgartools 的结构化接口或降级方案。
2. **yfinance 现金流表可用性**：HANDOFF §4 验证过利润表（5 个季度），
   **现金流表没验过**。取不到就砍掉第 2 条标准，改成 5 条。
3. **正文长度与 token 成本**：抽出来的 MD&A 实际多长，
   决定 stage1 是否需要先做一次压缩。

探测结果直接决定标准是 6 条还是 5 条，以及材料层要不要降级 —— 先探再写。

## 12. 与既有系统的关系

- **不改 P3 任何行为**。只做三处纯增量改动：`store.py` 加两张表、
  `outbox.KINDS` 加 `"pool"`、`schedule.plans()` 加一个 plist
- `run_pool.py` 排在 `run_daily.py` 之后 —— 不是为了读它的结果，
  而是要等它触发的 ingest 把当日价格/Reddit/EDGAR 写进库
- **`analysis/watchlist.py` 完全不动**：日报那一节继续用「前 10 排除 + 跃升」的老规矩；
  「前 20 全收」只是 `deepread/pool.py` 的入池口径。两者服务不同目的，不合并
- 复用 outbox / notify / launchd，不新建投递机制
- `run_portfolio.py`（P2）完全不受影响
