截至：2026-08-31

`run_lean.py` 的完整说明：架构、参数、数据源与凭证、实测数据、已知问题、未验证项、

## 架构：7 个节点，只有一个用 opus

```text
Python 预取证据
  ↓
Market · Sentiment · News · Fundamentals   4 个分析师（sonnet，各 1 次调用）
  ↓
Bull Researcher → Bear Researcher          多空辩论（sonnet，各 1 次）
  ↓
Research Manager                           判官（opus，采样 3 次取众数）
  ↓
评级 + 理由 + 操作要点
```

复用上游**同一批** agent 工厂和 prompt，但编排是 `lean/pipeline.py` 自己写的线性驱动——
选定的 7 个节点没有条件路由，不需要 LangGraph。上游的 `setup.py` / `conditional_logic.py` /
`trading_graph.py` 一行未改，`run_analysis.py` 随时能跑完整版。

砍掉的是 Trader、激进/保守/中立三个风险辩论者、Portfolio Manager。它们全部在
Research Manager **之后**执行，砍掉不影响评级；而每一个都要完整读一遍四份分析师报告，
是输入端最贵的部分。

**为什么只有判官用 opus**：它是全链方差最大的一步——前 6 个节点在描述证据，它要把证据
塌缩成一个分类标签。固定同一份辩论采样 5 次，sonnet 4/5 一致，opus 5/5。

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--date` | 今天 | 分析日期。**历史日期下新闻源基本不可用**，见已知问题。 |
| `--model` | `sonnet` | 分析师和多空辩论用的模型。 |
| `--deep` | `opus` | 只给 Research Manager。改成 `sonnet` 会明显降低评级一致性。 |
| `--evidence` | `prefetch` | `prefetch` Python 取完不给工具（默认）｜`hybrid` **不推荐**：实测 24 个分析师节点零工具调用，不带来任何新证据，只多付 15–30% 成本并降低评级一致性，见已知问题 1｜`tools` 上游原貌。 |
| `--tool-rounds` | `2` | `hybrid`/`tools` 下的工具轮次上限。没有它，模型可无限申请工具，而每轮都要重发全部上下文（实测单轮输入曾达 43,728 token）。 |
| `--judge-samples` | `3` | 判官重复采样次数，取众数。每多一次约 +$0.02。 |
| `--rounds` | `1` | 多空辩论轮数。**不要设 0**：上游的轮次判定会让空方直接不发言。 |
| `--analysts` | 四个全开 | 逗号分隔，可选 `market,sentiment,news,fundamentals`。 |
| `--full-sentiment` | 关（用压缩版） | 退回上游原版情绪分析师。压缩版省 59% 输入、35% 成本，评级未见变化。 |
| `--long` | 关 | 取消**所有**节点的字数上限。**不是调节字数的正确工具**：实测增量里只有 5% 落在真正起作用的 fundamentals 节点，33% 被 sentiment 吃掉（而它置信度受数据源封顶，见已知问题 4），market 的输出反而变短。单票 9.8 分钟 / $0.82，是默认档的 3 倍时间。要调字数改 `WORD_LIMITS`。 |
| `--lang` | 简体中文 | 输出语言。必须显式指定，否则不同模型会输出不同语言。 |
| `--save` | 关 | 各节点原文落盘到 `local-data/tradingagents/lean/`。 |

**字数预算**（`lean/pipeline.py` 的 `WORD_LIMITS`，不是命令行参数）：Fundamentals 与
News 为 400 字，其余节点 180 字。**不是所有节点都缺字数**——依据是取消全局上限后的增量
分布：fundamentals 只占 5% 却带来了全部差异，market 增量为负，sentiment 占 33% 但换不来
更可靠的结论。辩论和判官在分析师循环结束后显式复位到 180，防止上限泄漏下去。

## 数据源与凭证

全部走 yfinance 等免费源。**你唯一需要配的是 `FRED_API_KEY`**（免费申请：
<https://fred.stlouisfed.org/docs/api/api_key.html>），它提供 CPI、核心 PCE、失业率、
联邦基金利率、10 年期国债、收益率曲线。不配的话 News 分析师的宏观判断只能写 unknown。

### 怎么配

```bash
cp .env.example .env      # .env 已被 Git 忽略
# 编辑 .env，填上 FRED_API_KEY=你的key
```

`.env` 优先，其次是仓库根的 `.env`（`lean/env.py`）。**按绝对路径查找，不依赖当前
工作目录**——上游用的是 `find_dotenv(usecwd=True)`，从别处运行就读不到，将来接 launchd
定时跑时 cwd 不可控。显式传入的环境变量（`FRED_API_KEY=xxx python …`）始终优先于文件。

跑起来时会打印一行凭证状态，不打印 key 本身：

```text
凭证 FRED_API_KEY✓ ｜ ALPHA_VANTAGE_API_KEY✗
```

`ALPHA_VANTAGE_API_KEY` 是价格/指标/基本面/新闻的**替代**供应商，yfinance 已够用，不必配。

**不要设置 `ANTHROPIC_API_KEY`**：一旦存在，Claude Code 会静默改用 API 按量计费而不是
你的订阅。程序里有守卫会直接报错退出（可用 `STOCKWATCH_ALLOW_API_KEY=1` 明确放行）。

体检结果（`tools/check_sources.py`，2026-08-30）：12/14 可用。

| 分析师 | 拿到的证据 |
| --- | --- |
| Market | 180 天 OHLCV 压成摘要（区间/涨跌/分位/成交量/最近 5 根 K 线）+ 10 个技术指标的最新值 |
| Fundamentals | 28 项基本面快照（**单位已归一**）+ 三张季度报表提取 10 行，**同比与预期 EPS 倍数由 Python 计算** |
| News | 7 天个股新闻（按字符截断）+ 全球宏观新闻 + Polymarket 预测市场 |
| Sentiment | yfinance 新闻 + StockTwits 30 条 +（**Reddit 已停用**，见下） |

指标由 Python 全算后只交最新值，同比由 pandas 计算——**确定性数值不由 LLM 产生**
（`CLAUDE.md` 第 2 条）。补上报表摘要是实测必须的：只给 28 项快照时分析师给不出任何
增长数字，报告里写满 unknown。

**单位归一**（2026-08-31）：yfinance 的比率字段有三种口径，而原始输出是**裸数字**。
实测后果——AMD 的 `Debt to Equity: 6.361` 被读成 6.36 倍杠杆写进空方论据，真实值是
**0.064 倍**（全样本最低）；NVDA 的同一个 `16.971` 在不同运行里被读出"几乎零杠杆"和
"高杠杆"两个相反结论。三种口径已逐个用 `totalDebt/Equity` 与真实股息率反算核实：
`Profit Margin` / `Operating Margin` / `ROE` / `ROA` 是小数（×100），`Dividend Yield`
本来就是百分数，`Debt to Equity` 是百分数（现在百分比和倍数都给）。认不出的字段原样
保留，来源给非数值也保留原文——不猜、不丢。

**Reddit 已停用**（2026-08-31）：`lean/sentiment.py` 不再实时抓 Reddit，该数据段正在迁移到
独立的预抓取管线（`lean/reddit_prefetch.py`，见 [Reddit 预抓取接口](reddit-prefetch.md)）。

停用期间注入的是**显式停用标记，不是空串**——空串会让分析师写出"社区无人讨论"，把
"我们没去取"变成"市场没有声音"，正是 `CLAUDE.md` 第 3 条禁止的"缺失数据变成空成功"。
措辞对齐 `load_cached_reddit` 的缓存缺失分支，接线前后分析师看到的形状一致。

- **接线点**：`sentiment._reddit_block()`，函数体换成 `load_cached_reddit(ticker, trade_date).text`
  即可，调用方不用改。
- **降级可见**：桩会打一条 `tradingagents.dataflows.reddit` 的 warning，经 `SourceWatch`
  显示为 `Sentiment✗（Reddit 降级）`。
- **实测**（AMD 两次）：分析师都写明"Reddit 数据源本次不可用…confidence 降级为 low"，
  未出现伪造的"社区无人讨论"。
- **耗时影响：无。**实测 `fetch_reddit_posts(AMD)` 只要 **0.3 秒**，而整轮是 ~200 秒。

**预期 EPS 倍数**（2026-08-31）：`Forward EPS / TTM EPS` 由 Python 算好写进证据块。
这是 Forward PE 便不便宜的全部前提——AMD 的 Forward PE 30.1 看着温和，成立前提是 EPS
从 3.91 涨到 15.45（3.95 倍）。180 字上限下的分析师从没做过这步除法（见已知问题 1）。
TTM EPS 非正或字段缺失时写 `unknown` 并说明原因，不输出负数让人当增长率读。

## 实测数据

**耗时构成（AMD，2026-08-31 实测三次）**：整轮 197–203 秒里，LLM 生成 112–116 秒、
CLI 启动开销 83–88 秒（9 次调用 × 约 9.5 秒固定开销）、**Python 取数合计只有 2–5 秒**
（market 0.7s + fundamentals 0.9s + news 0.2s + reddit 0.3s，且 yfinance 有本地缓存）。
即这条管线 **97% 以上的墙上时间由 CLI 决定**，去掉任何一个数据源都不会变快；能动的
只有"减少调用次数"和"减少生成量"两个杠杆。

全部 NVDA / AMD，2026-08-28 与 08-30，本机 macOS + `claude` CLI 2.1.250。

**成本与耗时（lean 默认配置）**

| | 上游 12 节点原貌 | lean 默认（6 只票实测，08-30） |
| --- | --- | --- |
| 调用次数 | 17 | 9 |
| 输出 token | 47,473 | 4,863–6,672（均 5,674） |
| 输入 token | ~331,000 | 27,955–41,934（均 33,324） |
| 墙上时间 | 11.8 分钟 | 175–193 秒（均 184 秒） |
| 挂牌价折算 | $5.10 | **$0.20–0.23（均 $0.21）** |

早先记的 `$0.11–0.15 / 2.1 分钟` 来自 2026-08-28 的少量样本，**已被 6 只票的实测取代**。

10 只票约 $2.1、31 分钟（串行）；20 只票约 $4.2、1.1 小时。**并行会撞 Reddit 限流**
（已知问题 5）。

**evidence 档与字数的对照实验**（AMD，2026-08-30，同一天同一份证据，判官各采样 3 次）：

| 配置 | 评级 | 输入 tok | 输出 tok | 耗时 | $ |
| --- | --- | --- | --- | --- | --- |
| prefetch 默认（改动前） | Overweight 3/3 | 33,890 | 6,117 | 3.2 分钟 | 0.21 |
| hybrid（改动前） | Underweight 3/3 | 34,833 | 6,263 | 3.2 分钟 | 0.24 |
| prefetch `--long`（改动前） | Underweight 3/3 | 92,627 | 35,394 | 9.8 分钟 | 0.82 |
| **prefetch 默认（改动后）** | **Overweight 2/3 · Hold 1/3** | 34,348 | 7,005 | 3.4 分钟 | **0.26** |

改动后判官的理由里同时出现了空方的估值算术（"Forward PE 30.1 倍要求 EPS 从 3.91 跃至
15.45"）和被修正的杠杆（"负债/权益 6.36%"，此前是空方论据，现在成了反驳空方的依据）。
即：**以 1/3 于 `--long` 的成本拿到了同一条论证主线**。评级没有翻到 Underweight，而是
变成分歧——此前的 Underweight 3/3 有一部分建立在错误的 D/E 前提上。

**评级一致性**：补上报表摘要并改用 opus 判官后，三个批次各 3 次共 9 次全部一致
（NVDA Overweight 3/3 ×2 批、AMD Overweight 3/3）。**该结论早于上面的字数改动**，
改动后的一致性尚未重测。

**改动前**（sonnet 判官、无报表摘要）：同一只票同一天重跑 5 次得到 3 种评级
（Overweight 3、Underweight 1、Hold 1），横跨加仓与减仓两个相反方向。

**耗时构成**：生成约占一半，另一半是 CLI 启动开销（每次调用固定约 9 秒，与模型和
prompt 都无关，只跟调用次数有关）。

## 已知问题

**1. 输出字数上限会改变评级方向。**这条原本写的是"`hybrid` 与 `prefetch` 给出不同评级、
原因未查清"，并归因于"差异来自证据本身"。**该归因已证伪**（6 只票 × 2 档共 12 次运行，
2026-08-30）：

- 两档的证据块**完全相同**——同一个 `evidence.gather()`、同一天、同一份输入；
- hybrid 的 **24 个分析师节点一次工具都没调过**（每个节点都是 `次=1 往返=1`），它没有
  取到任何新数据；
- hybrid 唯一做的事是往每个分析师的系统提示里塞一块**固定**的工具协议 + schema
  （Market +2,131｜Fundamentals +2,302｜News +2,744 token，6 只票上都是常数，与实测的
  协议块体积一一对应），并把生成通道从纯文本换成 `--json-schema` 结构化输出。副作用是
  分析师输出平均涨 **101%**。

真正的自变量是**输出字数预算**。`prefetch --long`（无工具块、证据相同、只放开字数）
独立复现了同一个 Underweight 3/3。原因：180 字里"营收 +50.1%、毛利率 39.8%→53.8%"
最好写——单个数字自带方向；而估值论证需要多步才能成立（Forward PE + Forward EPS +
TTM EPS + 做除法 + 讲含义），一条 bullet 装不下。**字数上限系统性偏向好写的多头论据。**

已据此改动（2026-08-31，见下方"字数预算"）。AMD 复测：Overweight 3/3 → Overweight 2/3 ·
Hold 1/3，判官第一次同时拿到双方最强论据。**n=1，跨票重测尚未做。**

**2. 历史日期下新闻源基本不可用。**yfinance 新闻接口只提供最近若干篇——NVDA 报道量大，
最近 50 篇全在两天内，任何更早的窗口都查不到，且 limit 调到 200 也一样。跑当天日期不受影响。
证据层会把这种情况标成来源不可用并说明原因，不会伪装成"那周没有新闻"。

**3. Reddit 拿不到点赞/评论数。**RSS 接口不带这些字段，情绪分析师无法按参与度加权，
置信度因此结构性地偏低。官方 OAuth API 能拿到，但需要注册应用。

**4. 情绪置信度总是 Low。**StockTwits 只有 30 条样本、Reddit 无参与度数据，是数据源
能力上限，不是 bug。

**5. Reddit 的 20 秒最小间隔是进程内的。**串行跑批不受影响（每只票间隔远超它），但
**并行跑多只票会撞限流**，需要改成文件锁。

新增的 `prefetch_reddit.py` 已使用跨进程文件锁、持久化 `next_request_at` 和响应头
驱动的等待；这只解决新的预抓取路径。`run_lean.py` 尚未接入缓存，原有现场 RSS 路径
仍保留上述限制。

**6. `--effort` 参数对这些 agent 无效。**实测 `low` 与 `high` 的 thinking token 都是 0，
输出只差 5%——这些 prompt 不触发扩展思考。不要指望用它省钱。

**7. 一次 CLI 调用内部有 2–3 轮 API 往返。**用 `--json-schema` 时模型先发结构化工具调用、
再收一轮，prompt 会被重复计入，且模型自己的输出在下一轮变成输入。所以计费输入约是
prompt 的 3–5 倍，压缩 prompt 的收益也被这个倍数放大。

**8. 评级分布几乎没有区分度。**2026-08-30 那批 12 次运行里 **11 次是 Overweight**，
横跨半导体、大盘科技、银行、能源、必需消费五个板块。对单票研究影响有限，但目标流程要的是
**跨股票排名**，一个近乎恒定输出的评级器排不出 Top 10。**未定位原因，未验证是否与字数
上限的多头偏置同源。**

**9. `unknown` 判定不可靠。**AMD 复测中判官写"回补至 50 日均线（数值 unknown）"，但
50 日均价 506.08 就在证据里，同一次运行的其它段落还引用了它。即模型会对手上已有的数字
报 unknown。**单次观察，未量化发生率。**

## 未验证

- **字数改动只在 AMD 上跑过一次**（n=1）。多头偏置是否被系统性纠正，需要跨票重测才能说。
  400 这个数值也没有做过消融——实测 fundamentals/news 的输出都没顶到上限，说明 300 可能
  同样够用。
- **`--long` 的数字全部来自 1 次运行**（1 只票）。其中 sentiment 占 33% 增量这一项尤其不稳
  （它在 12 次运行里输入量从 4,216 跳到 22,351）。20 只票 3.3 小时 / $16.4 的外推只是量级。
- **样本仍然偏小**：evidence 对照跑过 6 只票（半导体、大盘科技、银行、能源、必需消费），
  但只有 1 个日期，且是周日休市快照。震荡市与财报窗口下的表现未知。
- **一致性的归因是模糊的**：opus 判官与报表摘要是同时引入的，无法确定 9/9 一致靠的是哪一项。
- **压缩情绪只在 NVDA 上验证过评级不变**，其他票未测。
- **单位归一后的评级影响只在 AMD 上观察过**，其余 5 只票未重跑。
- 批量、并行、调度、投递、通知：**全部未实现，也未测试**。

**单次评级不应作为交易依据。**终端打印的判官采样分布（如 `Overweight 3/3 一致` 或
`Overweight 2/3 Hold 1/3 ⚠ 结果分歧`）才是判断可信度的依据。

## 产品边界与冲突

V2 的产品边界（见下）写明排除 Trader、Portfolio Manager 和交易决策。当前状态：

- **`lean/` 管线符合边界**：它止于 Research Manager，不含 Trader / Portfolio Manager。
  但 Research Manager 本身会输出 Buy/Sell 评级和仓位措辞，这仍与 `CLAUDE.md` 第 1 条
  （"不提供直接买入或卖出指令"）有张力，**尚未处理**。
- **`run_analysis.py`（上游原貌）明确越界**：它照原样保留 Trader 和 Portfolio Manager，
  输出目标价和分批建仓指令。它只能人工调用来观察上游行为，**不得接入任何自动流程、
  报告或通知**。

产品边界原文：

- 研究与证据整理是范围；不下单、不连接自动交易执行。
- 不承诺价格预测、收益预测或投资结果。
- 数据缺失、来源失败和验证失败必须可见，不能静默变成空成功或自动负分。

`vendor/TradingAgents/` 是 [TradingAgents](https://github.com/TauricResearch/TradingAgents)
`a33fd4c`（Apache-2.0，**已核实**可改编再分发）的副本。改动共 6 处，清单与理由见
